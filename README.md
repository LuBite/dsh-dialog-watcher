# dsh-dialog-watcher

> 让 DSH 知道"你刚才跑的东西卡在一个 Windows 弹窗上了"。

DSH（DeepSeek Harness）插件。常驻枚举桌面上的阻塞性弹窗（程序错误框 / SmartScreen 拦截 / 安装向导 / 凭据请求 / 系统任务对话框），判断它是**哪个会话的命令**引起的，然后把一条「事件提醒」注入该会话。模型收到后可以自行判断，并通过 `dialog_action` 工具代点按钮——**不抢前台、不激活窗口**。

**当前版本：1.1.0**

---

## 它解决什么问题

你让 AI 帮你跑一条命令，命令拉起一个 GUI 程序，程序弹了个错误框卡住——AI 那边其实是"命令没有返回"，它不知道屏幕上有个窗口在等人点。于是它可能一直等，或者反复重试。

这个插件把"屏幕上出现了什么、属于谁、有哪些按钮"变成一条结构化事件送进对应会话，让模型能自主处置：继续、取消、或者告诉你需要你亲自处理。

## 工作原理

```
[探测器子进程]  PowerShell + Add-Type(C#) —— Win32 EnumWindows + UIA 双路
      │  每行一个 JSON（window / gone / clickResult）
      ▼
[宿主插件]  会话命令账本(ledger) → 证据分级(attributor)
      │      拦截器弹窗走"进程会话标记"锚，其余走多路线索组合
      │      强证据直接注入；中证据走「双命令双弹窗」二次确认 + 5 条互斥
      ▼
[注入器]    agent.steer( createUserMessage({
      │        source: { kind:'plugin:dialog-watcher', form:'notice', summary } }) )
      ▼
[模型]      收到事件提醒 → 判断 → 调 dialog_action 代点
```

**归属判定按确定性强弱依次尝试**（不依赖窗口文本、不做进程快照 diff）：

| 顺序 | 线索 | 说明 |
|---|---|---|
| **0** | **被拦截进程的会话标记** | 拦截器弹窗（防火墙 / UAC / SmartScreen / 杀软）专用：窗口属于**拦截器**而非被拦的程序，所以改读"被拦截一侧"进程环境里的 `DSH_SESSION_ID`；会话唯一即确定 |
| 1 | **人工指认** | 在面板里把某个程序绑定到某个会话，之后它的弹窗一律按强证据处理 |
| 2 | **SmartScreen「应用」字段** | 该字段与某会话命令里的文件名精确匹配（SmartScreen 父链天然断裂，这是唯一可靠途径） |
| 3 | **exe 线索** | 弹窗进程的可执行文件名出现在某会话命令文本里（含 `node` / `powershell` 这类裸命令名），且时间窗吻合 |
| 4 | **owner 链** | 弹窗的 owner 窗口所属进程，属于某会话命令拉起过的程序 |
| 5 | **纯时间窗** | 弹窗落在唯一会话的命令区间内（**进程创建时刻**与**弹窗出现时刻**两个锚都试） |
| 6 | 弱证据 | 该会话在弹窗出现前 90 秒内有过活动（无内容证据，只入池不注入） |

> 只有第 0 条会读目标进程的 PEB 环境块（单次约 0.06 ms，**任何失败都返回"未知"并降级，不会报错也不会误判**）；其余线索都不做跨进程内存读。

**去重**：只按"同一个窗口"去重。判定为该会话触发的弹窗每次都通知，不存在"某程序注入过就不再通知"的规则。

### 系统安全询问卡片（`system-consent`）

Windows 11 的「Windows 安全中心」询问卡片（防火墙放行、应用权限等）不是标准对话框：

- 它的顶层窗口是一个**空壳**：`Shell_SystemDialogProxy`，尺寸 `0x0`、没有子窗口
- 真正显示内容的卡片 `Shell_SystemDialog` 与全屏变暗遮罩 `Shell_SystemDim` **无法被 `EnumWindows` / `EnumThreadWindows` 枚举到**（实测枚举 666 个顶层窗口也拿不到它们）
- UIA 对它的边界报 `Infinity`，桌面树里查不到它的元素，**按钮文字完全拿不到**

插件对这类窗口的做法：

1. **检测**：以 `Shell_SystemDialogProxy` 为锚点（加入类名白名单，并豁免最小尺寸限制）
2. **定位**：`WindowFromPoint` 网格采样求出卡片包围盒，再对四条边二分精化到 ±1px
3. **按钮**：GDI 截取卡片 → 取**卡片左右边距的颜色**作基线（那几列永远是按钮行底面的颜色，不可能是按钮）→ 比基线亮 `5` 以上即算按钮 → 在**底部带（高度的 80%~96%）**内做**列投影**找出按钮矩形
   - 不能用全卡统计：卡片正文与按钮行是**两种不同的底色**，且**哪种更亮取决于主题**（浅色：正文 255 > 按钮 250；深色：正文 43 ≈ 按钮 45），任何全局阈值都会失效
   - 不能只用单行扫描：扫描线若穿过按钮文字，会把一个按钮切成两段（实测 2 个按钮变 4 段）
   - 只能搜底部带：卡片最底一行的描边、以及上方正文区，都会污染带检测
4. **点击**：`SetCursorPos` + `mouse_event` 在按钮中心发真实鼠标点击；点击前用 `WindowFromPoint` 复核该点仍属于本卡片

所有坐标都是**运行时测量**的，没有任何硬编码像素值，并且探测器启动即 `SetProcessDPIAware()`，因此换分辨率、换缩放比例都不需要改代码。

> 实测环境：3840×2160 @150%（DPI 不感知时进程会看到虚拟化的 2560×1440@96，坐标全体错位 1.5 倍——这正是早期"点不中"的真实原因，与遮罩拦截无关）。

## 安装

### 方式零：从 GitHub 直接安装（推荐）

```bash
dsh plugin --profile <profile> add github:LuBite/dsh-dialog-watcher
```

> **DSH Desktop（桌面端）** 请在应用内 **设置 → 插件** 里安装。桌面端的 profile 由应用独占管理，命令行改不了它。

---

### 方式一：随 profile 挂载（本地开发）

1. 把本目录放进 profile 的 `node_modules`：

```
~/.dsh/profiles/desktop/node_modules/dsh-dialog-watcher/
```

2. 在 profile 的 `package.json` 里加依赖与 bundle：

```json
{
  "dependencies": { "dsh-dialog-watcher": "link:<本目录的绝对路径>" },
  "dsh": { "profile": { "bundles": [ "...", "dsh-dialog-watcher" ] } }
}
```

3. 在 profile 目录下执行一次 `pnpm install`，让 pnpm 建好目录链接
4. 重启 DSH

> **必须是目录链接，不要手工复制成实体目录。** `link:` 依赖在 `node_modules` 里的形态是链接；如果放的是实体目录，pnpm 下次安装会尝试把它移走重建，遇到占用就是 `EPERM`。

### 方式二：临时挂载（无 bundle 声明的场合）

把下面这段写进 `~/.dsh/cordis.patch.yml`：

```yaml
- insert:
    - id: dsh-dialog-watcher
      name: 'dsh-dialog-watcher'
```

本包已有 `dsh.bundle` 声明，**两条路径不要同时用**，否则会报 duplicate loader entry id。

## 使用

### 面板

插件在 **`shell.overlay`** 槽位挂了一个**全局悬浮面板**（不随会话切换重建，会话列表页也会显示）：

```
弹窗监控    [开]  [关]
允许代点    [开]  [关]
弹窗记录    [查看]
吸附        [开]  [关]
```

| 控件 | 说明 |
|---|---|
| **弹窗监控** | 探测器总开关。关闭后探测器进程退出，零后台占用 |
| **允许代点** | 是否允许模型代点弹窗按钮（本插件提供的 `dialog_action` 工具）。**探测关闭时自动一并关闭，重新打开探测不会自动恢复**（需要手动再开） |
| **弹窗记录** | 展开记录面板：运行状态 / 最近事件（等级、动作、依据）/ 未归属池（可一键指认给某会话）/ 程序→会话绑定表 |
| **吸附** | **开**（默认）：面板自动贴在「回合一键开关」插件组正下方并跟随布局，拖动禁用；没有任何固定插件组时贴在会话内容区左上角。<br>**关**：顶部出现拖动把手（⠿），可自由拖动，位置重启后保持 |

当宿主 API 不可达时，开关会置灰并显示一行橙色提示，**不会静默失效**。

### 模型侧工具 `dialog_action`

**这是本插件自己注册的工具**（不是通用能力，也不依赖任何其它插件）。插件加载后它出现在会话工具表里；「允许代点」关闭或探测关闭时，调用会返回 `click-disabled` / `probe-disabled`。

模型收到提醒后可以调用：

| 参数 | 说明 |
|---|---|
| `window_id` | 提醒里给出的窗口句柄，如 `0x2A15B6` |
| `action` | `invoke`（点按钮）｜`close`（发 WM_CLOSE）｜`wait`（什么都不做） |
| `intent` | 仅 `invoke`：`ok` / `cancel` / `run` / `dontrun` |
| `button_text` | 仅 `invoke`：精确按钮名（与 `intent` 二选一，优先） |

**安全护栏**：只能操作探测器报告过的窗口，其它句柄一律返回 `unknown-window`。点击走 UIA Invoke，失败回退 Win32 `BM_CLICK`，不移动鼠标、不激活窗口。

## 配置

配置文件 `~/.dsh/dialog-watcher/config.json`（首次通过面板改开关时生成）：

| 键 | 默认 | 含义 |
|---|---|---|
| `probeOn` | `true` | 探测总开关 |
| `clickOn` | `true` | 允许代点 |
| `busyMs` / `idleMs` | 1500 / 5000 | 有会话运行 / 全部空闲时的扫描间隔（毫秒） |
| `ledgerRetentionMs` | 600000 | 命令结束后命令账本的保留时长 |
| `mediumTimeoutMs` | 600000 | 中证据挂起多久后转入未归属池 |
| `timeWindowBeforeMs` / `timeWindowAfterMs` | 2000 / 10000 | 强证据时间窗（命令起止向外扩多少毫秒） |
| `weakWindowMs` | 90000 | 弱证据"时间接近"的阈值 |
| `throttleWindowMs` / `throttleMax` | 60000 / 3 | 同会话注入节流 |
| `goneNotify` | `true` | 已提醒的弹窗消失后发"阻塞已解除"通知 |
| `debug` | `false` | 无归属的窗口也写事件日志 |
| `whitelist` | `[]` | 额外永不上报的 exe 文件名（叠加在内置名单上） |
| `muteUntilMs` | `0` | 临时静音截止时间（仅内存，不落盘） |

修改 `busyMs` / `idleMs` 会立即重启探测器生效；其它项下次判定时生效。

## 事件日志

每次检测 / 归属 / 注入 / 代点都会落一行 JSON：

```
~/.dsh/dialog-watcher/events/YYYYMMDD.jsonl
```

| 字段 | 含义 | 正常值 |
|---|---|---|
| `ev` | 事件类型 | `window` / `inject` / `gone` / `api-registered` |
| `decision.action` | 最终动作 | `inject-strong` / `inject-medium` / `pending` / `pool` / `ignore` |
| `decision.level` | 证据等级 | `strong` / `medium` / `weak` / `none` |
| `decision.sessionId` | 归属到哪个会话 | 应为发起命令的那个会话 |
| `decision.diag` | 诊断信息（仅 medium 时出现） | 命中/覆盖的 exe 线索，用于解释"为什么不是强证据" |
| `ok` | 注入是否成功 | `true` |
| `ev:"handler-error"` | 内部异常 | **应恒为 0 条** |

## 运行行为

- **探测器是常驻子进程**，由宿主进程拉起（不经过会话 shell）。异常退出后 **2 秒自动重启**；连续失败 5 次后转入 **60 秒一次**的慢速重试，直到成功或探测被关闭。
- **扫描间隔自适应**：有会话在运行时 `busyMs`（默认 1.5 秒），全部空闲时 `idleMs`（默认 5 秒）。
- **探测器的工作目录在 `%TEMP%\dsh-dialog-watcher\`**，不是插件安装目录——这样运行期间不会锁住安装目录，卸载 / 升级 / 包管理器整理依赖都不会 `EPERM`。该目录平时为空，可随系统临时文件清理；脚本与 C# 全部用绝对路径引用。
- **关闭探测 = 探测器进程退出**，不在后台留任何东西；重新打开会重新拉起。

## 自测

```powershell
# 一键自测（会在桌面真实弹一个测试对话框并在数秒内自动点掉）
powershell.exe -NoProfile -ExecutionPolicy Bypass -File test\run-tests.ps1

# 状态机单测（不依赖 DSH，可单独跑）
node test\cases.js
```

单测覆盖：强证据直注、basename 命中、单次中证据不注入、双命令双弹窗委婉注入、5 条互斥各拒绝一次、节流合并、无证据丢弃、SmartScreen 应用字段、owner 链、gone 解除、账本区间与重试链、exe 线索提取、措辞分级、Injector 服务缺失降级等。

## 已知局限

1. **孤儿进程漏报**：命令结束超过 `ledgerRetentionMs`（默认 10 分钟）后才弹出的对话框，其命令区间已从账本过期，最多只能走中证据/入池路径。这是"宁漏勿错"的既定取舍。
2. **中证据二次确认有等待窗口**：单次中证据不注入，要等同一程序在同一会话再弹一次；挂起超过 `mediumTimeoutMs`（默认 10 分钟）转入未归属池。
3. **「同一次调用的重试链」识别依赖近似关联**：DSH 未公开 job 与 tool-call 的显式关联，插件用"5 秒内最近的 tool-call"近似。若重试换了新的 callId，该条互斥退化为不触发（行为回落到基础双命令规则）。
4. **弹窗出现瞬间抢前台是程序自身行为**：插件无法也不应阻止。插件保证的是**它自己的点击不抢前台**（点击前后做三次前台采样比对）。
5. **只覆盖当前交互桌面**：多用户 / 远程桌面下，其它登录会话的弹窗看不到。
6. **子会话（subagent）不注入**：避免把噪音送进临时子代理。
7. **识别范围**：Win32 标准对话框（`#32770`）、凭据框、TaskDialog、被识别为 SmartScreen 的 UWP 外壳，以及 Windows 安全中心系统询问卡片（`Shell_SystemDialog*`）。除此之外完全自绘的窗口不识别。
8. **系统询问卡片的按钮没有文字**：这类窗口的按钮标签由 XAML 绘制且不暴露给 Win32/UIA，只能按位置识别——**最左是肯定/允许，最右是否定/取消**。这是 Windows 各语言版本的统一排布，但插件无法逐字核对你看到的是什么。
9. **系统询问卡片的处置有持久后果**：点「允许」会为该程序写入永久放行入站规则，点「取消」会写入永久阻止规则，且同一路径**只询问一次**。插件点完无法回滚，要改只能由用户到防火墙设置里手动调整。
10. **第三方杀软自绘拦截窗可能检测不到**：探测器只认 6 种标准窗口类名；火绒 / 360 等自绘窗口若类名不在其中会直接漏掉（**目前未支持**）。
11. **拦截器归属对第三方杀软只是理论覆盖**：目前只实测验证了 Windows 防火墙询问（`PickerHost.exe`）；火绒等杀软走同一段代码（已在拦截器特征表内）但**未实测**。
12. **会话标记可能过期**：进程可能持有已删除会话的 `DSH_SESSION_ID`；插件会照用该 id，若会话已不存在则注入失败并记入事件日志。

## 不做什么

- 不做 hook（不用 `SetWindowsHookEx`）；除**拦截器弹窗归属**需要读目标进程的环境块（只读 `DSH_SESSION_ID`，失败即降级）外，不读写其它进程内存
- 不调用 `SetForegroundWindow` / `ShowWindow` 去抢焦点
- 不自动点击任何**未被探测器报告过**的窗口
- 不做规则化代点：点不点、点什么，一律由模型判断，安全等级只改变建议措辞

---

## 运行环境

- Windows（依赖 Win32 `EnumWindows` + UIA）
- DSH（DeepSeek Harness）0.2.x
- 探测器用系统自带 PowerShell + .NET Framework（无需额外安装）
- 归属用到的进程环境读取，普通用户权限即可读同用户进程；权限不足的进程自动降级，不会报错
